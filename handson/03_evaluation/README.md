# Step 3 オフライン評価で品質を上げる（40 分）

## このステップでやること
1. 評価データ（3 件）を MLflow の **評価データセット** として登録する
2. スコアラー（採点の物差し）を決めて評価し、エクスペリメントで結果を見る
3. **Genie Code** で、NG になった理由を調べる
4. 原因に合った直し方で直し、もう一度評価して **全件 OK** にする

## 評価データ
[eval_dataset.json](eval_dataset.json) の 3 件です。1 件は「入力（企業特性）」と「期待値」の組です。
期待値には、業務部門が考える、その会社の **あるべき答え** を書きます。どの評価データでも、書く項目は同じ 2 つです。

| 期待値のキー | 書くこと | 例 |
|---|---|---|
| `expected_tier` | あるべき Tier（A / B / C） | `"B"` |
| `expected_points` | あるべき答えのポイント（文章の箇条書き）。点数・段階・次のアクションなど、確かめたいことを書く | `["④企業規模・予算が段階 4 と評価されている。…"]` |

> **最初は NG が出ます。** 評価データは、いまのエージェントでは満たせない業務部門の期待を含んでいます。
> NG の原因はそれぞれ違い、直す場所も違います。

## スコアラー
どの評価データにも、同じ 4 つのスコアラーを使います。

| スコアラー | 種類 | 見ること |
|---|---|---|
| `output_schema_valid` | コード | 出力に必要な項目がそろっているか |
| `axis_levels_valid` | コード | 観点ごとの点数が、選んだ段階の範囲に入っているか |
| `tier_matches` | コード | Tier が `expected_tier` と同じか |
| `meets_expected_points` | LLM ジャッジ | `expected_points` のポイントを、すべて満たしているか |

## 演習

### 3-1. 評価のノートブックを動かす（Omnigent・Databricks の画面）
評価のしくみ（データセットの登録・スコアラー・結果の表）は誰が書いても同じになるので、用意してあるノートブック（`03_evaluation/solution/03_evaluate`）をそのまま使います。
このステップで大事なのは、評価の結果を読み、NG の原因を調べて直すところです（3-2・3-3）。
1. [exercise/prompt_evaluate.md](exercise/prompt_evaluate.md) のプロンプトを Omnigent に送り、評価データとスコアラーを説明してもらう
2. `03_evaluation/solution/03_evaluate` を、ウィジェット `agent_dir` を `../../my_work` にして実行する。実行の仕方は 2 通りあります。
   - **A（おすすめ）: Omnigent に実行してもらう** — Omnigent が「このまま実行しますか？」と聞いてくるので「はい」と答える。
     終わると、結果の要点と **実行の画面の URL** が返ってくるので、URL を開いてセルの出力を見る
   - **B: 自分で実行する** — ワークスペースの自分の handson フォルダの `03_evaluation/solution/03_evaluate` を開き、ウィジェット `agent_dir` に `../../my_work` を入れて、右上で **サーバーレス** を選んで **すべて実行** する
3. **エクスペリメント** → `agent_handson_scoring` → **評価** タブで、いま作られた評価を開く
4. 評価データごとに、どのスコアラーが NG かを見る。NG の行を開くと、スコアラーの理由とトレースが見られる

### 3-2. NG の理由を Genie Code で調べる（Databricks の画面）
評価の画面やトレースを開いたまま、右上の **Genie Code**（Assistant）を開いて質問します。
質問の例は [exercise/genie_code_questions.md](exercise/genie_code_questions.md) にあります。

調べるときの観点:
- エージェントの出力（段階・点数・根拠）は、採点基準（`rubric.py`）どおりか
- 採点基準どおりなのに NG なら、**評価データの期待と採点基準のどちらが正しいか**（業務の判断）
- エージェントが知らない情報（CRM にない事情）が必要ではないか
- 文章の書き方の指示（プロンプト）が足りないのではないか

### 3-3. 直してもう一度評価する（Omnigent・Databricks の画面）
原因ごとに、直す場所を選びます。

| 直す場所 | どんなときに直すか |
|---|---|
| Managed Agent Memory | CRM などのデータにない、会社ごとの事情を採点に入れたいとき |
| 採点基準（`rubric.py` の段階・点数・補足） | 業務部門の判断と、採点基準の決めごとが違うとき |
| プロンプト（`rubric.py` の `SUMMARY_PROMPT` など） | 出力の文章に、書いてほしいことが書かれていないとき |

採点基準を変えたら `RUBRIC_VERSION` を上げます（評価の結果を版ごとに比べるため）。
直したら `solution/03_evaluate`（`agent_dir` は `../../my_work`）をもう一度実行し（Omnigent に「もう一度評価を実行して」と頼めば、直したファイルを反映して実行します）、**全件 OK** になることを確かめます。
エクスペリメントの **評価** タブで、直す前と後の評価を並べて比べてみます。
