# Step 4 Model Serving にデプロイし、Review App で人のフィードバックを付ける（30 分）

## このステップでやること
1. Step 3 で直したエージェントを MLflow に記録し、Unity Catalog に登録する
2. Model Serving にデプロイする（Review App も一緒にできる）
3. エンドポイントを呼び、デプロイ後のトレースが同じエクスペリメントと Delta テーブルに入ることを確かめる
4. Review App で採点結果に 👍／👎 とコメントを付け、エクスペリメントに残ることを確かめる

## 認証の考え方

| 使うもの | 認証 | 設定 |
|---|---|---|
| 基盤モデル・埋め込みモデル・AI Search のインデックス | エンドポイントの資格情報 | 記録するときに「使うリソース」として宣言する（`SystemAuthPolicy`） |
| Managed Agent Memory | 呼び出したユーザー本人の資格情報（On-Behalf-Of） | `UserAuthPolicy(api_scopes=["unity-catalog"])`。Memory はリソースとして宣言できないため |
| トレース | エンドポイントの資格情報でエクスペリメントに送る | 設定は不要（`agents.deploy` がエクスペリメントを指定する）。Delta テーブルへの同期は、Step 2 で有効にした自分のジョブが行う |

個人用アクセストークンなどの資格情報を、エンドポイントに渡す必要はありません。

呼び出したユーザーの資格情報で Memory を読むので、Memory を読む権限がないユーザーがエンドポイントを呼ぶとエラーになります。
Review App でほかの人にも試してもらう場合は、その人に Memory の読み取り権限（`READ_MEMORY_STORE`）を付けます。

## 演習

### 4-1. デプロイのノートブックを作って実行する（Omnigent・Databricks の画面）
1. [exercise/prompt_deploy.md](exercise/prompt_deploy.md) のプロンプトを Omnigent に送る
2. できた `my_work/04_deploy` を実行する。実行の仕方は 2 通りあります。
   - **A（おすすめ）: Omnigent に実行してもらう** — Omnigent が「このまま実行しますか？」と聞いてくるので「はい」と答える。
     終わると、結果の要点と **実行の画面の URL** が返ってくるので、URL を開いてセルの出力を見る（デプロイの完了まで待つので 20〜25 分かかる。待っている間に、下の画面を見ておく）
   - **B: 自分で実行する** — ワークスペースの自分の handson フォルダの `my_work/04_deploy` を開き、右上で **サーバーレス** を選んで **すべて実行** する
3. **サービング** → 自分のエンドポイント（`_config.py` の `ENDPOINT_NAME`）を開き、準備ができるまで待つ（15〜20 分）

> 待っている間に: エンドポイントの画面の **イベント**（デプロイの進み具合）と、**使うリソース**（宣言した基盤モデル・インデックス）を見ておきます。

### 4-2. エンドポイントを呼ぶ
1. ノートブックの「エンドポイントを呼ぶ」セルの出力で、採点の結果が返ってきていることを確かめる（A で実行した場合は、ノートブックの最後まで自動で進みます）
2. **エクスペリメント** → **トレース** で、いま呼んだトレースが増えていることを確かめる
3. 15 分ほどあと（4-3 のあと）で、ノートブックの最後のセルを実行し、デプロイ後のトレースと Review App のフィードバックが `scoring_traces` テーブルにも同期されたことを確かめる

### 4-3. Review App で人のフィードバックを付ける（Databricks の画面）
1. ノートブックに表示された Review App の URL を開く（チャットの画面）
2. 入力欄に、次の例のどちらかを、そのままコピーして貼り付けて送る（1 行の JSON です）

   **例 1: 見込みが高そうな会社（重要インフラ・古い制御系・直近の指摘）**
   ```json
   {"company_id": "R001", "company_name": "北陸ガスネットワーク株式会社", "industry": "ガス", "is_critical_infra": true, "regulated": true, "legacy_scale": "高", "security_staffing": "逼迫", "size_class": "大", "public_exposure": "中", "recent_trigger": "2026年4月、供給管理システムの未修正の脆弱性を外部から指摘され、緊急点検を実施", "existing_relationship": "取引なし（新規）", "key_facts": ["従業員 約8,200人", "供給管理の制御系を長期運用", "セキュリティ担当は数名で兼務が多い"], "summary": "重要インフラ×古い制御系×直近の外部指摘。"}
   ```

   **例 2: 見込みが低そうな会社（クラウドネイティブ・小規模・体制は十分）**
   ```json
   {"company_id": "R002", "company_name": "株式会社クラウドリンクス", "industry": "SaaS（業務アプリ）", "is_critical_infra": false, "regulated": false, "legacy_scale": "低", "security_staffing": "十分", "size_class": "小", "public_exposure": "中", "recent_trigger": "なし", "existing_relationship": "競合の脆弱性診断サービスを導入済み", "key_facts": ["従業員 約180人", "すべてのシステムをクラウドのマネージドサービスで運用", "専任のセキュリティチームが自社で運用"], "summary": "クラウドネイティブで自社で修正を当てる対象が小さい。"}
   ```

   普通の質問（例: 「あなたはどんなエージェントですか？」）を送ると、エージェントが使い方と入力の例を返します。
3. 回答に 👍 か 👎 を付け、理由をコメントに書く
   （例: 「次のアクションが具体的でよい」「情報不足の観点の確認事項が営業目線でない」）
4. **エクスペリメント** → **トレース** で、いまのトレースを開き、付けたフィードバックが **評価（assessment）** として残っていることを確かめる

> **ポイント**: 人が付けたフィードバックは、トレースと一緒に保存されます。NG のついたトレースを集めて評価データに足せば、
> 次の評価（Step 3 と同じ流れ）でその観点も確かめられるようになります。

## うまくいかないとき
- デプロイで `Dependencies do not exist` のエラーが出たとき: エンドポイントに残っている古いバージョンが、もうないもの（消したインデックスなど）を使っています。
  **サービング** → 自分のエンドポイント → **削除** で消してから、もう一度デプロイします。
  （模範解答のノートブックは、新しいバージョンの準備ができたら古いバージョンを外すので、通常は起きません）
模範解答 [solution/04_deploy](solution/04_deploy.py) を実行します（ウィジェット `agent_dir` は直した後のエージェントを指しています）。
