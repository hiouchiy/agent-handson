# Omnigent に送るプロンプト（Step 2 エージェントを作る）

このプロンプトには、使う機能や書き方は書いていません。**業務の言葉で、作りたいものと振る舞いだけを書きます。**
それをどの技術で実現するかは、Omnigent が「開発の決まり」（[../../DEV_GUIDE.md](../../DEV_GUIDE.md)）と Databricks のスキルを見て決めます。

プロンプトは 2 回に分けて送ります。1 回目で、要件をどの機能で実現するかの設計を見せてもらい、2 回目で作ってもらいます。

## 1 回目: 設計を見せてもらう

**このプロンプトで頼んでいること**: 要件を読んで、どの機能を使ってどう作るかを、コードを書く前に見せてもらう。

```
## 作りたいもの
法人向けセキュリティサービスの見込み顧客を、0〜100 点と Tier（A/B/C）で採点する AI エージェント。
営業担当が、どの会社から提案に行くべきかを決めるのに使う。

## 入力
会社ごとの特徴（業種・規模・システムの古さ・インターネットに公開しているシステム・セキュリティ人材の状況・
最近の出来事・当社との取引）と、会社ID。

## してほしいこと
- 採点基準（handson/02_agent/rubric.md）の 5 つの観点と関係性の補正ごとに、段階・点数・根拠を出す。
  観点どうしは関係ないので、同時に採点してよい
- 点数が、選んだ段階の点数の範囲から外れていたら、理由を伝えて 1 回だけやり直させる。それでも合わなければ点数を出さない
- 過去の受注事例から似ているものを探して、採点と提案の参考にする
- 採点の共通ルールと、会社ごとの申し送りを覚えておいて使う。頼まれたときは、採点の結果も次回のために覚えておく
- 合計と Tier は計算で出す（AI に足し算させない）
- 最後に、営業向けの評価コメント・次のアクション・根拠を書く（点数は変えない）
- 情報が足りない観点は低めに付けて、「情報不足」と印を付ける
- 会社の特徴が入っていない質問には、エラーにせず、使い方を返す

## 出力
handson/README.md の「スコアリングエージェントの仕様」のとおり。

## できたら
コードはまだ書かずに、次を見せてください。
1. 要件の 1 行ごとに、どの機能でどう実現するかの対応表（開発の決まりの対応表を使う）
2. 処理の流れ（どの順に何をするか）と、それぞれの入出力
```

## 2 回目: 作ってもらう

**このプロンプトで頼んでいること**: 1 回目の設計で、エージェントを作ってもらい、用意してある動作確認のノートブックで 1 社を採点してもらう。

```
## やりたいこと
さきほどの設計で、エージェントを作ってください。

## 確かめ方
用意してある動作確認のノートブックで 1 社を採点して、結果が表示されること。
実行してよいか、先に聞いてください。1 回直しても動かないときは、それ以上直さずに私に知らせてください。
```

## 動かしてみて、うまくいかないとき

Omnigent が実行したときは、エラーを見て自分で直してくれます。1 回直しても動かないときは、次のどちらかで先に進みます。
- 技術の中身まで書いた [詳しい版のプロンプト](prompt_build_agent_detailed.md) の 2 回目を送り直す
- 模範解答の `agent.py`（[../solution/agent.py](../solution/agent.py)）を `my_work/` にコピーする
